## The one rule behind most native bugs
Codemagic only runs `npx cap copy ios` (web assets + config), NEVER `cap sync`.
So the committed `ios/` folder is the source of truth for everything native:
- **Every new Capacitor plugin's pod must be added to `ios/App/Podfile` by hand**, or the plugin silently no-ops/throws in TestFlight builds. This bit three times: HealthKit ("not available on this device"), Preferences (native bearer token never saved → every auth call 401), SocialLogin.
- Info.plist usage-description strings must live in the committed `ios/App/App/Info.plist`. `scripts/ios-permissions.sh` re-applies + verifies them on every Codemagic build and fails loudly if any are missing (a missing `NSCameraUsageDescription` is a hard crash + Apple rejection).
- `ios/App/App/capacitor.config.json` is regenerated by `cap copy` — never hand-edit; edit `capacitor.config.ts` and re-run `npx cap copy ios`.

## HealthKit entitlement
`ios/App/App/App.entitlements` must contain ONLY `com.apple.developer.healthkit = true`.
**Why:** adding `com.apple.developer.healthkit.access` turns on the "Verifiable/Clinical Health Records" capability, which needs special Apple approval and fails signing with "Provisioning profile doesn't include the HealthKit Access capability". The app only reads workouts.
Entitlements are wired via `CODE_SIGN_ENTITLEMENTS = App/App.entitlements` in BOTH Debug and Release configs of project.pbxproj. One-time manual prerequisite (done): HealthKit capability enabled on App ID com.tacfit.app in the Apple portal.

## Provisioning profiles (codemagic.yaml step "Force a fresh provisioning profile")
Codemagic automatic signing reused stale cached profiles missing new entitlements. The yaml step deletes cached/stale profiles and mints a fresh one each build (fresh profiles inherit the App ID's current capabilities).
- Do NOT use `fetch-signing-files --create` — it also tries to create a distribution certificate and hits Apple 409 "already have a current Distribution certificate". Reuse existing cert ids; only `profiles create`.
- Codemagic CLI uses grouped subcommands (`profiles list/delete`, `bundle-ids list`, `certificates list`).
- `profiles create --save` needs `--profiles-dir "$HOME/Library/MobileDevice/Provisioning Profiles"` or it saves to the Xcode UserData dir and the entitlement-verification loop false-fails with "profile does NOT include HealthKit". A "missing HealthKit" report from that step almost always means wrong dir, not a real capability problem.

## Session/auth on native
- Session cookie `sameSite` is `'none'` in production (cross-origin Capacitor→backend), `'lax'` in dev.
- Native bearer token persists via `@capacitor/preferences`; an explicit 401 from `/api/auth/me` clears token+cached user and redirects to /login (self-heals installs with a cached user but no token). Network errors keep the local user (offline-friendly).

## Splash
Master splash: `scripts/assets/ios-splash-master.png` (2732×2732). `scripts/cap-build.sh` copies it into all three Splash.imageset slots. Splash changes need a NEW native build — reinstalling the same TestFlight build shows the old splash.

## Dead files
`npm run check` reports pre-existing TS errors only in `server/routes_clean_start.ts` and `server/routes_mood_section.ts` — dead files nothing imports; ignore them.
