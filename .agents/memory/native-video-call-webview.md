---
name: Native video call in WKWebView
description: What the embedded fairmeeting.net team call needs to work in the Capacitor iOS build
---

The team video call is a pure web embed (Jitsi external_api iframe at fairmeeting.net) — no Capacitor plugin, so no Podfile entry is needed for it.

Rules for it to work natively:
- `limitsNavigationsToAppBoundDomains` in `capacitor.config.ts` must stay **false**. There is no `WKAppBoundDomains` list in Info.plist, and App-Bound Domain limits can block camera/microphone (WebRTC/getUserMedia) inside the WKWebView.
- **Why:** the flag was `true` from boilerplate; nothing in the app relies on App-Bound Domains (no service workers natively, no WKAppBoundDomains key), so `false` is the safe WebKit default.
- Camera + microphone purpose strings (Info.plist AND `scripts/ios-permissions.sh` — keep both in sync) must mention team video calls, or Apple review can flag inaccurate purpose strings.
- Capacitor 6 handles the WKWebView media-capture permission prompt natively; iOS min version 16 is fine for iframe getUserMedia.
- The committed `ios/App/App/capacitor.config.json` is REGENERATED by `npx cap copy ios` (which Codemagic runs every build) — never hand-edit it; run cap copy to refresh it after changing `capacitor.config.ts`.

**How to apply:** any future change to the call embed or Capacitor iOS config — verify the flag stays false and purpose strings still cover actual camera/mic uses. Always have the user test the call on a real TestFlight build before submitting for review (camera/mic in WKWebView cannot be tested from the workspace).
